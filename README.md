# PathFinder-PRM: Process Reward Model with Fine-Grained Error Labels

Reproduction and extension of the PathFinder PRM framework for evaluating step-level correctness in mathematical reasoning. This project trains and compares four variants of a Process Reward Model (PRM) that differ in error-label granularity — from a single correctness judgment to a four-class error taxonomy — all on the same base model and data split for a controlled comparison.

## Overview

Given a math problem and a multi-step solution, the PRM evaluates each step's correctness. This project explores whether finer-grained error labels (identifying *what kind* of error occurred) improve the model's step-level discrimination ability compared to a simple correct/incorrect judgment.

### Four Label Granularities

| Version | Stages | Error Dimensions | Description |
|---------|--------|-----------------|-------------|
| **0class** | 1 (single) | correctness only | Directly predict whether the step is correct. Optional baseline. |
| **1class** | 2 (two-stage) | error → correctness | First predict whether any error exists, then predict correctness. |
| **2class** | 2 (two-stage) | math reasoning, consistency → correctness | Paper's original scheme: distinguish mathematical errors from consistency errors, then predict correctness. |
| **4class** | 2 (two-stage) | calculation, method, prior-step, domain → correctness | **Project extension**: further decompose into four fine-grained error types, then predict correctness. |

### Training Approach

- **Base model**: `Qwen/Qwen2.5-Math-1.5B-Instruct` (all four variants share the same base for controlled comparison)
- **Method**: LoRA fine-tuning with masked prediction at `<extra>` token positions
- **Special tokens**: `<+>` (correct), `<->` (erroneous), `<extra>` (prediction placeholder)
- **Online counterpart**: Qwen3-32B full-parameter fine-tuning for the 4-class setting (via cloud platform)

## Quick Start

### 1. Install Dependencies

```bash
pip install -r requirements.txt
```

> Requires Python 3.10+, PyTorch 2.x. The base model (`Qwen/Qwen2.5-Math-1.5B-Instruct`) is automatically downloaded from HuggingFace on first run. Set `HF_HUB_OFFLINE=1` if using a cached model.

### 2. Train and Evaluate All Four Versions

```bash
# Full pipeline: train + test + generate comparison table
python run_all.py

# Quick smoke test (small sample, 1 epoch)
python run_all.py --quick_test

# Train with specific settings
python run_all.py --epochs 4 --batch_size 4 --grad_accum 8 --max_length 1024

# Only re-test existing LoRA adapters
python run_all.py --skip_train
```

### 3. Run Individual Steps

```bash
# Train a single version
python train_.py --versions 2class --output_dir outputs/lora_2class --num_train_epochs 4

# Test a single version
python test_local_lora.py --model_dir outputs/lora_2class --version 2class \
    --output "test results/2class_results.jsonl"

# Generate comparison table
python compute_metrics.py --result_dir "test results"

# Merge per-sample results into CSV/XLSX
python merge_results.py --result_dir "test results"
```

## Training Details

### Masked Prediction Objective

Following the original paper's Appendix C protocol:
- The model input (`inputs` field) contains `<extra>` placeholders at label positions
- Logits are extracted only at `<extra>` positions; cross-entropy loss is masked everywhere else
- For two-stage versions (1/2/4class), stage 1 predicts error labels, stage 2 predicts correctness conditioned on stage-1 labels

### Memory-Efficient Training

To enable LoRA fine-tuning of a 1.5B model on consumer hardware (8GB unified memory):
- **Delta-only token embeddings**: Instead of updating full embedding/head matrices (~233M params via `modules_to_save`), only 3 new token rows (9,216 params) are updated via forward hooks
- **Target-only LM head**: The output projection runs only on `<extra>` target positions, avoiding full `(B, L, |V|)` logit materialization
- **Adafactor optimizer** with gradient checkpointing on MPS/CPU; AdamW on CUDA
- **Peak memory**: ~5–6GB (down from >10GB OOM)

### Hyperparameters (aligned with paper Table 6)

| Parameter | Value |
|-----------|-------|
| Epochs | 4 |
| Learning rate | 1e-4 |
| LR schedule | Cosine, warmup 0.1 |
| Gradient norm | 1.0 |
| Seed | 42 |
| Precision | bf16 (CUDA) / fp16 (MPS) |
| Gradient checkpointing | Enabled |
| LoRA rank | 16 |
| LoRA alpha | 32 |

## Dataset

- **Source**: 2,330 samples extracted from PRM800K (1,165 erroneous + 1,165 correct/suboptimal steps)
- **Split**: By `question_id` (5% validation, seed=42); all four versions share the same split
- **Error labels**: Auto-annotated by LLM, filtered for consistency with human annotations
- See [data description.md](data%20description.md) for full documentation

## Results

Results are generated in `test results/`. The comparison table includes:

- Per-dimension precision / recall / F1 / accuracy
- Step-level binary accuracy (erroneous vs. correct)
- Macro-F1 and exact-match rate
- 4-class aggregated to 2-class formulation (for cross-granularity comparison)
- Naive baseline ("predict every step as erroneous") and actual predicted-error ratio as diagnostics

Run `python compute_metrics.py` to regenerate after any test run.
